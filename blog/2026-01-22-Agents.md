Summary of Key Agentic Design Patterns


| Design Pattern | Description | Frameworks/Tools | Use Cases | Key Benefits | Challenges/Risks | Implementation Methodology | Source |
|----------------|-------------|------------------|-----------|--------------|------------------|---------------------------|--------|
| Retrieval Augmented Generation (RAG) | Retrieves information from external knowledge bases (vector/graph databases) and augments the prompt to ground LLM responses by searching a corpus for relevant information. | Vertex AI RAG Engine, Weaviate, Pinecone, Chroma DB, FAISS, LangChain, LlamaIndex, VectorDB, Annoy | Enterprise Q&A over internal wikis, customer support helpdesks, summarization of current events, personalized content recommendation, factual or domain-specific content retrieval (technical specs, policies). | Reduces hallucinations; provides verifiable citations; overcomes static training data knowledge gaps; enables agents to 'know' verifiable information beyond weights. | Information fragmentation (spread across chunks); high latency/cost for pre-processing; noise from irrelevant chunks; struggles with summarizing higher-level themes or connecting dots across multiple documents. | Indexing pipeline (chunking, embedding, vector store indexing); perform semantic similarity search; augment original prompt with retrieved context; generate response. | [1], [2] |
| Multi-Agent Collaboration / Coordination | A cooperative ensemble of specialized agents where high-level objectives are broken down and assigned to agents with specific skills, often coordinated through democratic, manager, or hierarchical strategies. | CrewAI, Google ADK (SequentialAgent, ParallelAgent, LoopAgent), Microsoft AutoGen, LangGraph, A2A Protocol, Ray, Orleans, Akka | Software development teams (Researcher, Coder, Tester, Documenter), marketing campaign generation, financial market analysis, supply chain management, financial trading, cybersecurity investigations, collaborative AI research. | Synergistic performance exceeding single-agent capacity; modularity and scalability; robustness against single-point failure; specialization and division of labor. | Communication and coordination overhead; potential for conflicting agent actions; complexity in orchestrating handoffs; higher token consumption/costs. | Define agent roles and backstories; establish communication channels (e.g., A2A protocol); implement hierarchical or decentralized networks; task decomposition into specialized agents. | [1], [2] |
| Reflection / Reflection Agents | A self-correction loop where an agent evaluates its own output, internal state, or past steps against criteria to identify and correct mistakes to improve performance. | LangChain, LangGraph, Google Agent Development Kit (ADK), CrewAI, ReflAct framework | Creative writing refinement, code debugging, complex problem solving, summarizing long documents with factual verification, high-stakes workflows, financial transaction orchestration, medical diagnosis, critical incident response. | Higher quality and accurate outputs; self-improvement without human intervention; reduces hallucinations; early error detection; prevents cascading failures. | Increased latency and cost due to multiple LLM calls; memory-intensive; added metareasoning overhead. | Producer-Critic (Generator-Critic) model; one agent generates a draft/action, a second agent critiques it against goal-state reflections, and the first agent refines the output. | [1], [2] |
| Tool Use (Function Calling) | Allows agents to interact with the real world by calling external APIs, databases, or executing code based on LLM reasoning. | LangChain, LangGraph, CrewAI, Google ADK (Google Search, Code Execution, VSearch), Vertex Extensions | Real-time weather retrieval, database updates, financial calculations, sending emails, smart home control. | Overcomes static training data limitations; enables data-driven actions; connects reasoning with execution. | Malformed tool outputs; service unavailability; security risks (needs principle of least privilege); rate limits. | Define tool purpose/parameters; LLM generates JSON for function call; orchestration layer executes tool and feeds result back to LLM. | [1] |
| Planning / Plan-Execute | An agent formulates a sequence of actionable steps to achieve a high-level goal, splitting the task into distinct planning and execution phases. | CrewAI, Google Gemini DeepResearch, OpenAI Deep Research API | Onboarding new employees, autonomous research synthesis, complex logistics, competitive analysis, complex multistep processes. | Enables handling of multi-faceted requests; allows adaptability (re-planning) when obstacles occur; clear decomposition and debuggability. | Risk of unpredictable behavior in open-ended plans; inefficiency if a fixed workflow would suffice; planning overhead and added latency. | Deconstruct high-level prompt into a research/action plan; separation of planner (long-horizon reasoning) and executor (invokes tools); execute plan iteratively and replan if needed. | [1], [2] |
| ReAct | Interleaves Reasoning and Action in an iterative loop: the model generates a thought, selects and invokes a tool, observes the result, and repeats as needed. | LangChain, LangGraph | Dynamic data analysis, multisource aggregation, troubleshooting, exploratory scenarios. | Ability to adapt midstream based on intermediate observations; transparency via 'chain of thought' which aids debugging. | Higher latency and computational overhead; increased API costs. | Model loops through thought-action-observation cycles; use of ZERO_SHOT_REACT_DESCRIPTION or CHAT_ZERO_SHOT_REACT_DESCRIPTION templates. | [2] |
| Routing | Introduces conditional logic to dynamically arbitrate between multiple potential actions, tools, or sub-agents based on user input or state. | LangChain, LangGraph, Google Agent Developer Kit (ADK) | Customer inquiry classification (e.g., routing to tech support vs. billing), automated data distribution, triage for AI coding assistants. | Enables adaptive and context-aware behavior; moves beyond rigid linear workflows; optimizes performance by selecting specialized tools. | Classification errors by the router LLM; increased complexity in state management; potential for non-deterministic execution paths. | Use LLM-based classification, embedding-based semantic similarity, or rule-based logic to decide the next node in a computational graph. | [1] |
| Parallelization | Executes independent sub-tasks, LLM calls, or tool usages concurrently rather than sequentially to reduce latency. | LangChain (LCEL), LangGraph, Google Agent Development Kit (ADK) | Information gathering from multiple sources, sentiment analysis on batches of feedback, travel planning (checking flights and hotels simultaneously). | Significant reduction in execution time for tasks with independent parts; improves system responsiveness. | Introduces complexity in design, debugging, and logging; increases computational cost/API quota consumption. | Identify non-dependent tasks; use asynchronous execution or multi-threading; aggregate results at a subsequent convergence point. | [1] |
| Prompt Chaining | Decomposes a complex problem into a sequence of smaller, manageable sub-problems where the output of one prompt is fed as input into the next. | LangChain, LangGraph, CrewAI, Google Agent Development Kit (ADK) | Information processing workflows, complex query answering, data extraction from unstructured sources, content generation, code refinement. | Introduces modularity, clarity, and control; reduces cognitive load on the LLM; improves reliability and debugging. | Instruction neglect; contextual drift; error propagation; hallucination if cognitive load is too high on a single prompt. | Break task into focused prompts; assign distinct roles; specify structured output formats like JSON for inter-step parsing. | [1] |
| GraphRAG | An advanced extension of RAG incorporating graph-based data structures (nodes and edges) to manage complex interrelationships. | Neo4j, graphrag (CLI), neo4j-graphrag-python, nano-graphrag | Global insights, thematic summarization, multihop reasoning, answering questions across scattered information. | Manages complex dependencies; performs better on large, messy, or narrative datasets than baseline RAG. | More expensive and complex approach to incorporate than standard chunking/vector retrieval. | Construct knowledge graph of entities and relationships; extract semantic triples; traverse graph at runtime for context. | [2] |
| Human-in-the-Loop (HITL) | Integrates human oversight and judgment into AI workflows to ensure ethical boundaries, safety, and accuracy. | Google ADK (Callbacks), LangChain, CrewAI | Content moderation, autonomous driving (complex handovers), loan approvals, medical diagnosis validation. | Enables responsible AI deployment in high-stakes sectors; improves system trust; provides learning data for reinforcement. | Lack of scalability; dependency on human expert quality; privacy concerns when exposing data to humans. | Establish escalation policies; use callbacks for manual intervention; human validates/reviews draft before final output. | [1] |
| Inter-Agent Communication (A2A) | An open standard (HTTP-based) allowing AI agents built on different frameworks to collaborate, delegate, and exchange info. | Google A2A Project, LangGraph, CrewAI, Google ADK, Salesforce, SAP | Multi-framework collaboration, automated workflow orchestration across different cloud platforms. | Interoperability between vendor-specific systems; fosters a modular ecosystem; allows dynamic discovery of skills. | Security/Authentication management; standardizing task state across heterogeneous frameworks. | Define Agent Cards (JSON-RPC 2.0); use synchronous request/response or streaming SSE; implement mutual TLS for security. | [1] |
| Guardrails / Safety Patterns | Layered defense mechanisms including input validation, output filtering, and behavioral constraints to ensure safe operation. | Google Cloud Vertex AI, CrewAI, Pydantic (Schema validation) | Preventing jailbreaking, filtering toxic language, ensuring brand safety, academic honesty enforcement. | Maintains user trust; protects organizational reputation; prevents manipulation and adversarial attacks. | Potential performance trade-offs; over-restriction can limit utility; requires continuous monitoring and refinement. | Sanitize inputs; use defensive prompting; implement 'before_tool_callback' for security checks; utilize Pydantic for structural validation. | [1] |
| Single-Agent | A single agent responsible for managing and executing all tasks, interacting directly with its environment. | LangGraph | Simple chatbots, order tracking, FAQs, data entry, code generation, narrow-scope tasks. | Simplicity; easier implementation/management; lower resource requirements and latency. | Performance degrades with too many tools; limited scalability for multifaceted tasks. | Unified prompt and graph; agent invokes tools if available up to a limit before responding. | [2] |
| Query-Decomposition | Iteratively breaks a complex question into subquestions, fetching answers for each to synthesize a final response. | SELF_ASK_WITH_SEARCH | Research, fact-based Q&A, knowledge retrieval across multiple facts. | Grounded retrieval accuracy; ensures facts are grounded in tool output before final response. | Requires multiple tool calls; higher latency due to sequential sub-queries. | Loop: 'What follow-up question do I need?' -> call tool -> synthesize final answer. | [2] |
| Reflex Agents | Direct mapping from input to action using 'if-condition, then-action' rules without internal reasoning traces. | Not in source | Keyword-based routing, single-step data lookups, basic automations. | Millisecond responses; minimal latency; predictable performance. | No multistep reasoning; limited expressiveness; no context beyond immediate input. | Direct trigger detection; calls appropriate tool immediately. | [2] |
| Deep Research Agents | Specialized agents for open-ended, highly complex investigations requiring hypothesis testing and synthesis. | Not in source | Literature reviews, scientific discovery, strategic market analysis, technical due diligence. | Management of multistage adaptive investigations; identifies key subtopics/data sources. | High compute costs; very high latency; fragility/reliance on quality of external data sources. | Combines planner-executor, query-decomposition, and ReAct loops into iterative research cycles. | [2] |
